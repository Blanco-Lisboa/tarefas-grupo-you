## 4. Aplicar as duas mudanças no banco: primeiro a 006, depois a 007

As duas mudanças são arquivos de texto com instruções para o banco:
- `supabase/006_envio_e_caderno_alheio.sql`: tarefa enviada cai no caderno de quem recebe; você lê o caderno do Matheus só para ler.
- `supabase/007_achados_lupa_4_5_11.sql`: os 3 consertos de segurança da Lupa (só funciona depois da 006).

Escolha UM dos dois jeitos.

### Jeito A: pedir a um terminal
Peça a um terminal: "aplique o 006 no projeto Supabase Tarefas - Grupo You". Vai abrir uma janela **Accept**: clique **Accept**. Se aparecer aviso de "destrutivo", pode aceitar: é falso alarme (o arquivo só troca regras de acesso, não apaga tarefa). Espere ele dizer que deu certo. Depois peça o 007 e clique **Accept** de novo.

### Jeito B: colar você mesmo no SQL Editor
1. Abra https://supabase.com/dashboard/project/uruhjlurcxpjhhgvuzwt/sql/new e confira no topo que o projeto é **Tarefas - Grupo You**.
2. Antes da 006, uma conferência rápida. Cole e clique **Run**:
   ```
   select to_regclass('public.fazendo_agora');
   ```
   Você deve ver: `fazendo_agora` no resultado. Se vier vazio (`NULL`), pare: falta o 005.
3. Abra o arquivo `supabase/006_envio_e_caderno_alheio.sql` (no VS Code ou Bloco de Notas), **Ctrl+A**, **Ctrl+C**. No SQL Editor, apague o que estiver lá, **Ctrl+V**, clique **Run**.
   Você deve ver: `Success. No rows returned`.
4. Só se o 006 deu Success: faça o mesmo com `supabase/007_achados_lupa_4_5_11.sql`.
   Você deve ver: `Success. No rows returned`.

Erro em vermelho? Não rode o próximo. Mande o print.
